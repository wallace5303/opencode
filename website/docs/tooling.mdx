读完这章，你能在本地把 opencode 跑起来、改完代码跑对检查、并理解配置与存储的底层约定。

## 环境要求

- **Bun 1.3+**（`packageManager` 锁定 `bun@1.3.14`）
- Node 也兼容，通过 `#db` 条件导入切换适配层
- 操作系统：macOS / Linux / Windows

## 常用命令

根目录（`../opencode`）：

```bash
bun install                      # 装依赖；postinstall 会跑 packages/core 的 fix-node-pty
bun dev                          # 跑 TUI，默认对着 packages/opencode
bun dev <directory>              # 对着指定目录跑（bun dev . = 对着仓库根）
bun dev serve [--port 8080]      # 无头 API server，默认端口 4096
bun dev web                      # server + Web UI
bun run --cwd packages/app dev   # Web UI 开发（先起 bun dev serve）
bun --cwd packages/desktop dev   # Electron 桌面端
bun lint                         # oxlint（根级）
bun typecheck                    # turbo 跑所有包的 typecheck
```

### ⚠️ 两个"不能在根目录做"的坑

1. **测试不能在根目录跑**。根 `package.json` 的 `"test"` 脚本是：
   ```json
   "test": "echo 'do not run tests from root' && exit 1"
   ```
   这是显式守卫。必须 `cd packages/xxx` 后再跑。

2. **类型检查不要直接用 `tsc`**。opencode 用的是 `@typescript/native-preview`（即 `tsgo`），快得多。每个包的 `"typecheck"` 都是 `tsgo --noEmit`。用 `bun typecheck`（turbo 串联）或进包目录跑 `bun typecheck`。

## 单包命令（以 `packages/opencode` 为例）

```bash
cd packages/opencode
bun typecheck                                 # tsgo --noEmit
bun test --timeout 30000 --only-failures      # 全量测试
bun test path/to/file.test.ts                 # 单个测试文件
bun test -t "name pattern"                    # 按名字跑单个测试
bun run test:httpapi                          # 跑公开 HttpApi（coverage/auth/effect 三模式）
bun run build                                 # 走 script/build.ts
./script/build.ts --single                    # 编译独立可执行文件
```

构建产物：`packages/opencode/dist/opencode-<platform>/bin/opencode`（如 `darwin-arm64`、`linux-x64`）。

## 代码生成（勿手改）

opencode 是**契约驱动**的：Protocol/Server 的 `HttpApi` 是权威契约，客户端代码由生成器产出。

| 产物 | 位置 | 生成命令 |
|---|---|---|
| Promise 客户端 | `packages/client/src/generated/` | `cd packages/client && bun run generate` |
| Effect 客户端 | `packages/client/src/generated-effect/` | 同上 |
| 旧版 JS SDK | `packages/sdk/js/` | `./packages/sdk/js/script/build.ts` |

- 改了 Protocol 或 Server 的 HttpApi → **必须**在 `packages/client` 跑 `bun run generate`。
- CI 用 `check:generated`（`generate` + `git diff --exit-code`）校验生成物是否最新。
- `src/generated*` 目录里的代码**不要手改**，下次生成会被覆盖。

生成器本体在 `packages/httpapi-codegen`，从 `protocol` + `server` 读取契约 IR，emit 出客户端。

## 类型检查

- 全局：`bun typecheck`（turbo 并行跑各包）
- 单包：`cd packages/xxx && bun typecheck`
- 工具：`tsgo`（`@typescript/native-preview`），**不是** `tsc`
- 配置：各包 `tsconfig.json`，根 `tsconfig` 通过 turbo 协调

## Lint 与格式化

- **Lint**：`bun lint` → oxlint（根级，配置 `.oxlintrc.json`）。还有 `oxlint-tsgolint` 做 TS 增量规则。
- **格式化**：Prettier，根 `package.json` 里：
  ```json
  "prettier": { "semi": false, "printWidth": 120 }
  ```
- **提交钩子**：`.husky/pre-push`。

## 配置系统（`src/config`）

opencode 的配置模块遵循**自导出模式**：每个配置子模块在文件顶部用 `export * as ConfigX from "./x"` 把自己导出为一个命名空间。

| 模块 | 自导出 | 职责 |
|---|---|---|
| `config.ts` | `Config` | 配置合并/加载/更新主服务 |
| `agent.ts` | `ConfigAgent` | agent 配置加载 |
| `command.ts` | `ConfigCommand` | command 配置 |
| `plugin.ts` | `ConfigPlugin` | plugin spec 解析与去重 |
| `paths.ts` | `ConfigPaths` | 配置文件路径发现 |
| `parse.ts` | `ConfigParse` | JSONC 解析 + Schema 验证 |
| `variable.ts` | `ConfigVariable` | 环境变量替换 |
| `managed.ts` | `ConfigManaged` | Desktop 管理偏好 |
| `markdown.ts` | `ConfigMarkdown` | Markdown 配置 |
| `tui.ts` | `TuiConfig` | TUI 配置 |

> 新增 config 模块时，**必须**沿用这个模式（`AGENTS.md` 明确要求）。

### Catalog（模型元数据）

Catalog 不在 opencode 包，在 **core** 包：

- `packages/core/src/catalog.ts` — `Catalog` 服务（`@opencode/v2/Catalog`），提供 provider/model 的 get/update
- `packages/core/src/models-dev.ts` — `ModelsDev` 服务（`@opencode/v2/ModelsDev`），从 [models.dev](https://github.com/anomalyco/models.dev) 拉取 provider/model 元数据（`Model`/`Provider` Schema、`CatalogModelStatus`）
- `packages/core/src/plugin/models-dev.ts:142` — 插件通过 `ctx.catalog.transform` 注入或修改 provider/model 元数据

opencode 侧 `provider/provider.ts` 用 `mapValues(modelsDev, fromModelsDevProvider)` 把 ModelsDev 数据映射成 `catalog`。新增 provider 优先往 models.dev 提 PR，而不是改 opencode 代码。

## 存储与 `#db`

`packages/opencode` 用一个 `#db` 导入别名，通过 package `imports` 条件切换 Bun/Node 适配层：

```json
"imports": {
  "#db": {
    "bun": "./src/storage/db.bun.ts",
    "node": "./src/storage/db.node.ts",
    "default": "./src/storage/db.bun.ts"
  }
}
```

代码里写 `import { ... } from "#db"`，运行时按条件解析：

<Tabs>
  <Tab title="Bun 运行时">
    解析到 `db.bun.ts`，用 `@effect/sql-sqlite-bun`（Bun 原生 SQLite）。
  </Tab>
  <Tab title="Node 运行时">
    解析到 `db.node.ts`，用 Node 适配的 SQLite 驱动。
  </Tab>
</Tabs>

这样上层业务代码不用关心运行时。

`src/storage/` 下可见：

- `storage.ts` — `Storage` 服务（`@opencode/Storage`），JSON 文件存储 + migration（基于 FSUtil + Git）
- `schema.ts` — re-export 所有 Drizzle 表定义（`SessionTable`/`MessageTable`/`PartTable`/`TodoTable`/`ProjectTable`/`WorkspaceTable`/`AccountTable`…，来自 `@opencode-ai/core/*/sql`）

### Drizzle 字段命名

**snake_case**。这样列名不必再用字符串重定义：

<Tabs>
  <Tab title="✅ 推荐">
    ```ts
    const table = sqliteTable("session", {
      id: text().primaryKey(),
      project_id: text().notNull(),
      created_at: integer().notNull(),
    })
    ```
  </Tab>
  <Tab title="⛔ 避免">
    ```ts
    const table = sqliteTable("session", {
      id: text("id").primaryKey(),
      projectID: text("project_id").notNull(),
    })
    ```
  </Tab>
</Tabs>

## 风格速查（来自 `AGENTS.md`，强制）

- 禁止别名导入（`import { foo as bar }`）和星号导入；需要命名空间时导入模块自身的导出，如 `import { Project } from "@opencode-ai/core/project"` 再 `Project.ID`
- 启动敏感路径用动态 `import()`，在**最窄作用域**顶部解构绑定，不要 `await import(...).then(...)` 链
- 依赖类型推断，避免 `any`；只在导出/必要时才写显式类型
- 单次使用的值就地内联，不要预先抽 helper
- `const` + 三元/早返回优先于 `let`/`else`
- 能 `.catch(...)` 就别 `try/catch`；纯同步解析的 helper 不要返回 `Effect`
- Effect 生成器里先 `const foo = yield* Foo.Service` 再调方法，不要嵌套 `yield*`
- 用 Effect schema 助手（`Schema.UnknownFromJsonString`、`Schema.decodeUnknownOption`）替代手写 `JSON.parse` + `Effect.try`
