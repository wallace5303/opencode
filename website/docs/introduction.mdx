这套文档用来拆解 [**opencode**](https://github.com/sst/opencode) —— 一个开源的 AI 编码 agent。它的本体在相邻的 `../opencode` 目录（Bun + TypeScript + Effect 4.0 monorepo）。本仓库（`opencode-docs`）只存放学习笔记与一个 [Mintlify](https://mintlify.com/) 文档站。

## 两条阅读线

文档分两条互补的线，按你的目标选：

- **参考线**（[功能](./features/cli-commands)、[实现原理](./internals/dependency-layering)）：回答「opencode 这块代码长什么样」——逐子系统拆解，附 `file:line` 源码引用，便于跳转核对。
- **build 线**（[自己造一个](./build/introduction)）：回答「如果我自己造一个，每步该怎么设计、能砍掉什么」——把各功能串成从零复刻一个 coding agent 的可复刻指南，每篇含「自建最小子集」。

想读懂 opencode 本身 → 参考线；想学会造同类项目 → 先走 build 线建全局观，再按需钻参考线。

## 怎么读

第一次接触：

1. [项目全景](./overview) 建立整体印象；
2. [架构分层](./architecture) 记住**依赖方向铁律**（Schema → Core/Protocol → Server；Client 绝不依赖 Core/Server）——它是理解一切的骨架；
3. 遇到不熟悉的词查 [术语表](./glossary)。

想动手造一个：

1. 从 [自己造一个 · 导读](./build/introduction) 进 build 线，按 01–08 顺序读；
2. build 线里提到「详见 internals/xxx」时，再跳进参考线深挖。

## 约定

- 引用源码一律 `packages/xxx/src/yyy.ts:行号`，相对 opencode 仓库根。
- 术语严格用 `CONTEXT.md` 规范词（如 **System Context**、**Provider Turn**、**Session Drain**、**Context Epoch**），不用「系统提示词」这类口语化说法。
- 文档基于 opencode `v1.17.13` 前后的代码状态，上游重构后 `file:line` 可能漂移。
