## 三条读懂 opencode 的线索

### 线索 A：依赖方向

`schema → core/protocol → server`，client 只依赖 schema/protocol，sdk-next 组合三者。看到任何"client 想 import core"的冲动，先回到 [架构分层](./architecture)。

### 线索 B：契约驱动

`protocol/api.ts` 的 HttpApi 是唯一契约 → server 实现 → codegen 生成 client → UI/sdk 用。改契约必须重生成。这条链路解释了为什么 opencode 能同时有 CLI/TUI/Web/Desktop/SDK 还不乱。

### 线索 C：内核在 core，编排在 opencode

`packages/core/src/session*` 是"怎么跑一次会话"（admission/execution/runner/system-context），`packages/opencode/src/session` 是"跑什么"（业务编排、工具、provider）。初学者最常在这两个包之间迷路。

## 动手入口

### 跑起来

```bash
cd ../opencode
bun install
bun dev                 # TUI
bun dev serve           # 无头 server (4096)
bun dev web             # server + Web UI
```

### 改一个小工具

1. 读 `packages/opencode/src/tool/read.ts`（最简单的工具之一）
2. 仿照它在 `tool/` 下加一个文件，导出 `ToolDef`
3. 在 `tool/registry.ts:198` 的 builtin 列表里注册
4. `cd packages/opencode && bun typecheck`
5. `bun dev` 起来后让 agent 调用你的工具

### 加一个 HttpApi 端点

1. 在 `packages/protocol/src/api.ts` 的某个 group 加 endpoint 声明
2. 在 `packages/opencode/src/server/routes/instance/httpapi/handlers/` 加 handler
3. `cd packages/client && bun run generate`
4. `cd packages/opencode && bun run test:httpapi`（coverage/auth/effect 三模式）
5. `bun run check:generated` 确认生成物已更新

### 调试 session 流程

1. 在 `packages/core/src/session/runner/llm.ts:168`（`runTurnAttempt`）下断点
2. 跟着双层循环走一遍：promote → reconcile → llm.stream → settle tools → needsContinuation
3. 看 `SessionInputTable` / `SessionMessageTable` / `SessionContextEpochTable` 的数据变化

## 易踩的坑

- **在根目录跑测试** → `do-not-run-tests-from-root` 守卫直接 exit 1。进包目录。
- **用 `tsc` 类型检查** → 慢且可能行为不一致。用 `tsgo`（`bun typecheck`）。
- **手改 `src/generated*`** → 下次 generate 被覆盖，CI `check:generated` 挂。
- **在 client 里 import core/server** → 分层违规。下沉到 protocol 契约。
- **桥接 V1 `SessionPrompt.loop`** → 违反 V2 约束。新代码走 core runner。
- **Drizzle 字段用 camelCase + 字符串列名** → 违反约定。用 snake_case。
- **别名导入 / 星号导入** → 风格禁令。需要命名空间就导入模块自身导出。
- **以为 Session V2 在 opencode 包** → 内核在 core。先看 `packages/core/src/session*`。
